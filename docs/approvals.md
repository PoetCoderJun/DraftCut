# 旧签名版包装路径 / Signed packaging approvals

干净成片现使用真实对话中的文稿批准，获批后自动交付，不要求终端签名；见[干净成片](../references/04-clean-cut.md)。以下为仍保留的签名版包装实现，不作为独立干净出片的前置条件。

DraftCut 使用 **口播稿审核 → 视频脚本审核 → 成片**。Agent 准备提案与审核包；用户批准准确版本。为了使模型不能仅写 `approved=true` 自批，生产入口要求由用户保管的加密 Ed25519 私钥签发的回执。Node 内置 crypto 实现签名，不新增云服务、账号或付费依赖。

本页是生产身份流程。明确授权的隔离模拟用户测试使用[独立测试身份](simulation-testing.md)，控制器在内部记录自然语言回复，不能要求模拟普通用户设置生产密钥或运行签名命令，也不能把测试身份提升成 owner 身份。两种回执不互相接受。

用户要求的是两次普通对话确认。下面的终端签名是**当前实现的后备路径**，仍增加了用户操作；这项使用缺口没有因补充文档而消失。既有自然语言 E2E 验证的是隔离模拟用户路径。实现无需手工 CLI 的生产确认，需要[可信宿主对话适配器](conversational-approvals.md)，不能直接接受 Agent 自填的聊天记录。

## 一次设置，由用户本人执行

在你自己的终端，从仓库目录运行：

```bash
python3 scripts/review_approval.py setup
```

输入至少 12 字符的私有口令并确认。身份文件保存在 `~/.config/draftcut/`，私钥以口令加密；生产验证读取这里的公钥，不接受项目内任选的公钥或 Agent 提供的替代信任。不要向 Agent、提示词、仓库、日志或其他人提供口令，不要让 Agent 代运行此设置。

本次开发和合成示例不会创建你的生产身份。只有在你要批准真实项目时才需要本人设置。

## 每一道审核，由用户本人确认

Agent 会给出本次审核包的 `request.json` 与 `review.md`。阅读完整审核稿、差异和字幕；试听代理／批准音频是可选辅助，不是签名批准的前提。在自己的终端运行：

```bash
python3 scripts/review_approval.py approve --request /绝对路径/本次审核包/request.json
```

工具再次检查请求是否仍为当前版本，展示完整审核文档和内容摘要。明确同意后输入提示中的 `APPROVE <摘要前12位>`，再输入私有口令。回执写入同目录 `approval.json`。口令通过隐藏终端输入，只经进程管道传给本机 crypto，不出现在参数、环境变量或文件中。

Agent 随后可以继续工作。口播稿批准只允许生成该版本正式原声音频；视频脚本另需一次批准。没有回复、模糊回复、模型自评、旧布尔值、伪造回执和错误签名都不能通过。

## 绑定与失效

第一道请求绑定源素材与转写 hash、全部词的决定／顺序、字幕、差异稿、代理、语义复核证据、项目 ID 与修订代次。第二道请求还绑定正式音频／字幕、导演脚本、完整结构化计划及素材 hash。

口播稿或语义证据变化后需重新生成审核包，两道下游批准失效。导演脚本／计划／素材变化后需重审第二道。恢复旧稿也不会恢复已被流程观察到失效的旧代次。重试只重用完全相同、仍有效的已批准产物；不覆盖旧版本。旧项目须显式迁移重新批准。

签名证明批准来自配置的持钥者且内容未变，不证明内容与听感已正确。与所有本机工具一样，它依赖你保管口令和生产公钥配置，以及运行代码未被替换；无法防御拥有你全部系统权限、口令或能改写执行器的攻击者。文稿复核、视觉检查及可选试听分别如实记录，未试听不阻断文稿审核。

## 合成示例

`examples/full-workflow/run.py` 使用公开定义的音调 PCM 和手写词时间戳，以及独立临时测试密钥。它演示状态转换，**不代表真实人类批准或真实 ASR／听感验收**。即使项目设置 `example_only`，验证器仍会核对源 PCM 和词表是否严格等于仓库合成 fixture；它不能授权真实录音或任意人物视频。测试身份不能进入生产信任路径。
