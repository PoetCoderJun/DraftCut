# 对话内确认

DraftCut 只有两次内容确认：完整口播稿和导演方案。Agent 必须把当前版本的完整可读正文直接展示在对话里；用户用自然语言明确表示同意后，Agent 自动继续。

用户不需要运行命令，也不需要配置身份、公私钥、口令、摘要或签名。`approval.json` 只是 Agent 自动写入项目目录的本地审计记录，用来把确认绑定到当前审核请求；它不是要求用户处理的加密回执。

## 什么算确认

“这版可以”“批准当前稿件”“按这个导演方案做”一类指向当前完整版本的明确回复可以继续。带修改条件、含糊回复、历史无关回复、Agent 自评和模拟用户回复不算真实用户确认。

## 版本变化

第一道确认绑定源素材、转写、逐词决定、字幕和文稿复核证据；这些内容变化后需要重新展示完整文稿并再次确认。第二道确认绑定精炼音频、字幕、导演脚本、结构化计划和素材；这些内容变化后需要重新展示导演方案并再次确认。

Agent 在确认后使用内部 `record-approval` 命令记录用户原话与当前请求摘要。用户无需知道或执行该命令。旧 `approved=true`、旧审核文件和其他项目的确认不能触发生产。

明确授权的隔离模拟用户测试仍按[测试说明](simulation-testing.md)保存独立测试记录，并始终标明 `owner_approval=false`；它不能转成真实用户确认。
