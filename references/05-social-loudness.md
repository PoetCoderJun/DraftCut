> **v2 审核边界：**以下为历史母带工具的信号处理参考。当前完整口播流程的正式母版绑定逐采样原声；直接变速或母带处理后的文件不能替换批准音轨，也不能靠旧授权绕过两次批准。需要此类处理时先明确新的审核与信号变换方案，当前生产门禁会拒绝未绑定的替换。`master_audio.py` 只作为独立诊断工具保留，不代表该选项已接入 v2 生产链。

# 倍速与口播母带

在用户要求倍速、母带、高响度，或报告爆音、发糊、刺耳、泵动时读取。用户的听感问题优先于响度目标；LUFS、真峰值和解码通过不能证明没有可听失真。

## 倍速只做一次

- 分别记录画面、音频、外部字幕各自的当前速度和共同时间原点；每项实际处理倍率为 `target_speed/该项当前速度`。例如画面已1.15倍、干净音轨仍1倍时，画面倍率为1，音频才用1.15。不要对已经1.15倍的母带再做 `atempo=1.15`。
- 整片变速时，保留已批准画面作为整体底片：HyperFrames `<video data-playback-rate="倍率">`，烧录字幕、人物和MG一起变速。外部SRT/章节时码按各自当前速度除以对应倍率，文字不变；用户明确纠正文字时只改指定词。
- 声音从同剪辑时间线、未做母带的源音轨重建，以 `atempo` 保留音高；已变速的WAV放入工程后，音轨播放倍率为1。不要用改采样率的方式制造变速。
- 画面保留批准的fps；时长按最终画面帧数确定。不能用 `-shortest` 掩盖音画速度或时长不匹配。
- 用户提出修订时先记录要求；涉及已批准信号或脚本变化的，按当前 v2 流程重新审核相应版本。

## 用户说爆音/发糊时

1. 保留被拒绝版，回到未做母带的源音轨。只把坏母带调小不能撤销已产生的失真。
2. 优先对照开头和用户指出的位置：源音轨、处理后的PCM、最终解码AAC。以相近播放响度比较，区分源录音失真、处理失真、编码问题与播放端过载。
3. 先撤去重压缩、makeup增益、追目标的额外 `volume`、饱和器及多级限幅；根据证据再加入需要的处理，不默认套高频增强/降噪/去齿音链。
4. 峰值低于0dBFS仍可能存在之前的削波、压缩/限幅失真、齿音或时间伸缩伪影。不要用“真峰值合格”否定用户的听感。
5. 无法试听时，明确记为 `listening.performed=false`，可交付重建版及技术报告，但不能宣称“爆音已确认消失”或“听感验收通过”。用户反馈是进一步修订证据，不设置额外的统一审批门。

## 响度目标按声音决定

- 温和口播/失真修复可先从约 `-14 至 -12 LUFS-I` 开始，保留句子起伏。
- 用户明确要“响度战争”时，可以尝试更高响度，`-10 至 -9 LUFS-I`是可选目标，不是必须达成的下限。出现失真、发糊、底噪抬升或持续限幅时退回更温和版本，并报告实际结果。
- 处理峰值通常留在 `-2 至 -1.5 dBTP`，最终解码AAC应不高于 `-1.0 dBTP`；平台再编码需要余量。LRA仅作辅助，不为了范围压平自然语气。
- 不把某一期的速度、LUFS、均衡和压缩参数变成全局固定配方。

## 固定信号，再做两遍测量

先把倍速、声道、必要的EQ/压缩等前处理写成无损预混文件，再测这个文件。第二遍必须使用同一信号及相同I/TP/LRA目标；初次测量若只是为确定LRA，确定目标后重新测量，不能沿用另一组目标的offset。前处理发生变化（包括新加压缩器、增益或变速）就重新测量，不能复用旧的 `measured_*`。

优先只使用一层测量驱动的归一化，不默认再叠加补偿增益和末级限幅。`linear=true`并不保证线性模式：峰值/LRA条件不满足时，FFmpeg会回退动态模式，必须记录实际 `normalization_type`。目标未达到时先评估余量与失真，不能仅按差值加增益。

可使用内置的保守入口；它不叠加独立压缩器/EQ，也不声称做过试听；归一化本身仍可能是动态处理：

```bash
python3 <skill-root>/scripts/master_audio.py \
  --source-audio "$prepared_audio" \
  --source-speed 1 --target-speed "$target_speed" \
  --duration "$approved_duration" \
  --target-lufs -13.5 --true-peak -2 \
  --output-dir "$output_dir/audio-master"
```

输出无损倍速源、24bit/48kHz WAV、AAC及 `audio-master-report.v1.json`。输出目录必须是新的空目录。`--subtitles`须同时提供 `--subtitle-source-speed`，按字幕自己的倍率生成时码副本；只改时码行，正文中的时间字符串不变。此入口是温和起点，不保证每个录音都无需进一步处理。

## 长度、封装与验收

- 倍速在前，母带在后。每次从无损预混继续，不反复转码已经处理的AAC。
- 延迟与长度分别检查：如果使用 `alimiter`，显式考虑 `latency=true`；使用任意有延迟的处理后，核对开头/中段/尾段同步。`asetpts`不能撤销真实波形延迟。
- 末端重采样后先 `asetpts=PTS-STARTPTS`，再 `apad,atrim=end_sample=round(duration*sample_rate)`，最后重置PTS；按样本数核对WAV及AAC长度，避免滤镜PTS偏移造成约一个AAC帧的尾部缺口。仅允许补偿编码/舍入尾差，不能用补静音修复错误倍速。
- 已批准画面只改音频时，`-map 0:v:0 -map 1:a:0 -c:v copy`替换音轨；母带AAC只编码一次，能直接复制封装时使用 `-c:a copy`。验证前后视频码流哈希不变。
- 对**最终解码AAC**复测LUFS-I、真峰值、LRA、音视频起点、尾差及解码；记录目标未达成的情况。检查字幕边界和倍速映射，不能只查文件存在。
- 试听覆盖开头、最高电平/齿音/爆破音、用户问题段；修复后用相近响度A/B比较。没有实际听过就保留待试听状态。
- 报告将 `technical_checks` 与 `listening` 分开。脚本将未达到请求响度目标单独列为检查失败，不能把安全但未达目标的输出当作已达目标；优先保留声音质量并明确记录目标调整。默认LRA不低于测得的源LRA，避免无意压缩动态。原始音轨读取启用严格解码错误检查。报告还分别记录倍速阶段和归一化阶段补删前的PCM样本数、补删尾差及AAC解码填充；仅声明时长一致不足以证明同步。
- 技术通过但未试听的总体状态为 `technical_passed_listening_pending`，不得用无条件 `passed` 暗示听感已合格。
