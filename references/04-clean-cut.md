# 文稿批准后自动交付干净成片

这是 DraftCut 默认的第一阶段交付。先在当前命令行／对话展示完整文稿、简短删改理由和疑点；用户明确批准当前版本后，立即在同一任务完成出片，不再要求“开始渲染”、试听或本人终端签名。只在用户明确限定“仅文稿、不制作”时停在文字交付。

## 批准与版本

宿主Agent必须读取真实的直接用户消息；按当前展示版本、素材和范围执行。修改条件不是批准，改变口播或剪辑后不能套用旧批准。`--approval-note` 只记录实际批准及范围，不是批准来源，也不证明加密真实性；不能伪造 owner 回执或升级模拟批准。该命令拒绝合成fixture与simulation工程，旧签名包装入口不接受这些对话记录作签名。

## 本地制作

沿用已复核的 `manuscript.json` 与 `compile_edit` 整数样本时间线。词语纠错不得改变实际保留音频；缺失词时间戳时，以已有ASR的真实短句边界为字幕提供证据，不编造逐词时间。先检查外置SRT内容和边界；干净画面默认不烧字幕。源文件不覆盖，输出放本项目新的独立目录。

```bash
python3 <skill-root>/scripts/render_clean.py \
  --project-dir "$project" --output-dir "$new_output" \
  --encoding hardware --approval-note "实际用户批准当前文稿的消息与范围" \
  --subtitles "$checked_srt"
```

固定单worker、逐段准确seek。人物画面与原声共用同一顺序和累计帧分配，保留原分辨率、比例和帧率。默认VideoToolbox硬件H.264；确实选择软件编码时显式传 `--encoding software`，不静默回退。只拼接原声PCM，不变速、不补词，不加MG、音乐、标题、调色或水印。内部生成的正式 `narration.wav` 与旁挂SRT用于后续制作；不把REVIEW-ONLY代理冒充正式母版。

## 验收

完整解码MP4；检查H.264/AAC、分辨率、fps、累计帧、音视频时长误差不超过两帧。逐采样核对原声拼接，并比较成片AAC解码波形；检查SRT毫秒边界在成片内，抽查开头、中段、尾段与最后一帧。试听可选，未试听如实记录。技术通过和实际观看分别说明，不伪称连续观看。

交付 `edited-video.mp4` 和 `final-clean.srt`，留存项目、映射、日志与质量报告。后续包装须用户另行要求及批准导演脚本，不自动包装、不自动发布。
